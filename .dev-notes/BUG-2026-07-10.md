# Bug: Incorrect OpenCode Scroll Port

**Date:** 2026-07-10

## Problem

The attempt to port OpenCode's scrolling behavior to our TUI resulted in an
implementation that:

1. **Did not compile** — private field `is_sticky_bottom` was accessed from
   `app.rs`
2. **Was completely different from OpenCode** — sticky scrolling, scroll
   accumulator, and acceleration logic were implemented in an ad-hoc way
   instead of being a faithful behavioral port
3. **Introduced overlapping rendering bugs** — UI elements overlapped while
   scrolling (the same bug that already existed before)
4. **Provided worse behavior** — unsmooth scrolling, unstable viewport, and
   broken auto-scroll

## Root Cause

- Not studying OpenCode's `ScrollBox` (`opentui`) in sufficient depth
- Implementing based on assumptions instead of porting the actual behavior
- Ignoring that OpenCode uses a rendering system based on the **scroll start
  position** (sticky scrolling), not post-render adjustments
- Mixing drag auto-scroll, sticky scrolling, and scroll accumulator logic
  without understanding how they interact in OpenCode

## Next Steps

1. Completely revert the changes to the last working commit
2. Study `ScrollBox.ts`, `scroll-acceleration.ts`, and how
   `session/index.tsx` in OpenCode uses scrolling
3. Study our `cosh-tui/renderables/scroll_box.rs` to understand the current
   architecture
4. Reimplement it as a faithful behavioral port rather than a custom
   reimplementation
