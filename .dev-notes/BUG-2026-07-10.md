# Bug: Port do Scroll do OpenCode - Implementação Incorreta

**Data:** 2026-07-10

## Problema

A tentativa de portar o comportamento de scroll do OpenCode para nossa TUI
resultou em uma implementação que:

1. **Não compilava** — campo privado `is_sticky_bottom` sendo acessado de `app.rs`
2. **Completamente diferente do OpenCode** — a lógica de sticky scroll, scroll
   acumulador e aceleração foi implementada de forma ad-hoc, não como um port
   comportamental fiel
3. **Bug de sobreposição** — elementos se sobrepondo durante o scroll (o mesmo
   bug que já existia antes)
4. **Comportamento inferior** — scroll não suave, viewport instável,
   auto-scroll quebrado

## Causa Raiz

- Não estudar o ScrollBox do OpenCode (opentui) com profundidade suficiente
- Implementar baseado em suposições em vez de portar comportamento real
- Ignorar que o OpenCode usa um sistema de renderização baseado em **scroll
  start position** (sticky scroll), não pós-renderização
- Misturar lógicas de auto-scroll de drag, sticky scroll, e scroll acumulador
  sem entender como elas interagem no OpenCode

## Próximos Passos

1. Reverter completamente as mudanças para o último commit
2. Estudar o ScrollBox.ts, scroll-acceleration.ts, e como o session/index.tsx
   do OpenCode usa o scroll
3. Estudar nosso cosh-tui/renderables/scroll_box.rs para entender a arquitetura
4. Implementar como um port comportamental fiel, não uma reimplementação
